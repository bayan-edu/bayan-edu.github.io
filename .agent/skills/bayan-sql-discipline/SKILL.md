# انضباط قاعدة بيانات بيان (SQL / RLS / دوال Supabase)

> يُستدعى قبل كتابة أو مراجعة أي SQL أو دالة أو سياسة RLS لمشروع بيان. الحُكم والتاريخ التفصيلي في وثيقة `STATE.md` بالمشروع؛ هذه خلاصتها التشغيلية اليومية.

## ٠ · لماذا هذا الانضباط

في ٥ سبتمبر ٢٠٢٦ أدّت قراءة `00_schema.sql` (لقطة قديمة) بدل الدالة الحية إلى استبدال `get_quiz` بنسخة أقدم ⇒ سقط نمط `gap` كاملاً من الإنتاج، ولم يظهر العطل عند التشغيل بل عند معلّم يحفظ سؤالاً. وفي ٧ سبتمبر حُجز رقم ملفٍّ مشغول فعلاً لأن `STATE.md` لم تُحدَّث بعد التطبيق بيوم واحد. كلا الحادثين سببه **قراءة وثيقة بدل مصدر حي**. هذه المهارة هي الحاجز ضد تكرارهما.

## ١ · قبل أن تكتب سطراً — استعلام "أين نحن؟"

شغّل جملة SQL واحدة (استعلامٌ واحد لا عدّة جمل — محرّر Supabase يعرض نتيجة آخر جملة فقط):

```sql
select n, title, coalesce(applied_at::date::text,'—') as طبق, note
  from sql_log order by sql_log_sort(n), n;
```

اقرأ منها:
- **الرقم التالي** — لا يُؤخذ من أي وثيقة، فقط من هذا الاستعلام.
- **آخر ثلاثة مطبّقة** — إن سبقت تاريخ "حيث انتهينا" في STATE.md فالوثيقة متأخّرة، لا تُؤخذ منها أرقام.
- **ثقوب في التسلسل** — رقمٌ بلا سجلّ إطلاقاً = قنبلة موقوتة (يُحجز مرّتين أو يُبحث عنه أبداً).
- **فجوات موصوفة** — لها `note` يشرح السبب؛ تُقرأ قبل السؤال عنها.

ونسخة الواجهة الحالية: `grep -n 'BUILD' js/ui.js`

## ٢ · سبع قواعد لا تُخرق

١. **لا `create or replace` قبل `pg_get_functiondef('public.الدالة(الوسائط)'::regprocedure)`.** اقرأ الحيّ ← قارن ← استبدل. لا تُصمَّم دالة من `00_schema.sql` — إنه لقطة مؤرَّخة لا حقيقة.
٢. **`STATE.md` حُكمٌ لا مصدر أرقام.** كل رقم منقولٍ فيه ينحرف؛ الاستعلام في القاعدة هو المصدر الوحيد.
٣. **لا تُحِل إلى ملفٍّ قبل أن يوجد.** "طبّق sql/58" نيّةٌ لا أمر — تحقّق أن الملف مكتوبٌ فعلاً قبل الإحالة إليه.
٤. **الفحص يُصاغ لكل حالةٍ بما يخصّها.** اختبارٌ واحد على أشياء مختلفة "فشل" لا يعني شيئاً، ويُعوِّد القارئ تجاهل الإنذار.
٥. **الفجوة تُرى والصمت لا يُرى.** رقمٌ ملغًى يُسجَّل بسببه، قرارٌ يُشرح في موضعه، عطلٌ مؤجَّل يُكتب.
٦. **اقرأ المصدر الحيّ قبل أن تُصمّم عليه.** `grep` على الجدول الفعليّ قبل `create table`/`alter` يعتمد عليه — لا افتراضاً من الاسم.
٧. **غيابٌ في وثيقةٍ مؤرَّخة ليس دليل عدم.** لقطة `00_schema.sql` تشهد بما كان يوم استُخرجت، لا بما ليس اليوم.

## ٣ · كتابة ملف SQL جديد

- الاسم: `NN_name.sql` — رقمٌ من استعلام §١، لا من أي وثيقة.
- **قابلٌ لإعادة التشغيل بالكامل:** `create or replace` · `if not exists` · `on conflict` · `drop constraint if exists` ثم `add`.
- **رأس الملف يقول "لماذا" لا "ماذا"** — الشيفرة نفسها تقول ماذا.
- **يفصل "معدَّلة" عن "منشأة"** بعنوانٍ صريح داخل الملف.
- **`grant execute`** صريحٌ لكل دالة جديدة — بلا هذا يسقط الوصول بصمتٍ يوم يُحكَم `EXECUTE`.
- **يُختم وجوباً، والسطر داخل نفس المعاملة إن أمكن:**

```sql
insert into public.sql_log (n, title, applied_at)
values ('NN', 'العنوان — بحرفه كما في رأس الملف', now())
on conflict (n) do update set applied_at = now();
```

`do update` لا `do nothing` — إعادة التشغيل تُحدِّث التاريخ ولا تُرفض. والملف يسجّل **رقمه هو فقط**؛ رقمٌ ملغًى أو مؤجَّل يُسجَّل بسطر `insert` مستقلّ بـ`note` يشرح السبب.

## ٤ · حدودٌ لا تُتجاوز

- ⛔ لا `delete` ولا `drop` على القاعدة الحيّة بلا إذنٍ صريح في الجلسة نفسها. اعرض دائماً تجربةً جافّة أولاً:

```sql
begin;
  -- الحذف
  select … as الباقي;   -- يُعرض للمستخدم قبل أي شيء
rollback;                -- يُستبدل بـ commit فقط بعد موافقة صريحة
```

- ⛔ لا تُشغَّل ملفات `sql/` القديمة — إعادة تشغيلها قد ترجع القاعدة إلى الوراء.
- ⛔ الملفات `69`–`71` ملغاةٌ نهائياً (أوامر هدمٍ جاهزة للنقر).
- 🔑 `service_role` يتخطّى RLS كلَّه — استعمل `anon` لأغلب العمل، ولا تُشغِّل بدور القوّة إلا لهجرةٍ تقتضيه صراحةً.

## ٥ · فحص RLS — نمطٌ ثابت

```sql
set local role authenticated;   -- المحرّر بدور postgres يتخطّى كل سياسة
select set_config('request.jwt.claims',
       json_build_object('sub', '‹uuid›')::text, true);
```

- `set_config` يوضع **داخل نفس جملة `from`**، لا في جملة سابقة — المحرّر يعرض نتيجة آخر جملة فقط.
- اختر مستخدماً يبلغ **مستوى الهدف فعلاً**، وإلا حجبه حارسٌ آخر فبدت الفتحة أضيق ممّا هي.

## ٦ · عند الختام — خمسةٌ لا يُترك منها شيء

```
① سطر sql_log ......... داخل الملف نفسه (§٣)
② قرارٌ لا يُقرأ من الشيفرة ⇒ تعليق الملف إن خصّه · STATE.md إن خصّ المنصّة
③ STATE.md §"حيث انتهينا" يُحدَّث فوراً: ما أُنجز يُشطب، وما ظهر يُضاف
④ تغيّرت الواجهة ⇒ BUILD يُرفَع في js/ui.js — ومعه MOD في كل وحدة تحمل ختماً
⑤ تغيّرت البنية ⇒ 00_schema.sql يُعاد استخراجه، ورأسه يُصحَّح من المتن
```

🔴 البند ③ هو الذي أوقع حادثة ٧ سبتمبر — تأخّره يوماً واحداً كفى لحجز رقمٍ مشغول. **و`STATE.md` تُرفع فعلياً إلى المستودع بعد كل تعديل** — نسخةٌ حيّة خارج Git تُصدَّق وهي كاذبة.

## ٧ · تذكيران للمشروع تحديداً

- **`dx_codes` هي ميزة المنصّة لا تفصيلةٌ فيها.** أي اقتراح يُفرغ التشخيص (يبسّطه إلى "صح/خطأ" بلا كود) يُرفض مهما بدا عملياً.
- **إن كان العائق محتوى لا تقنية** (دروسٌ غير موسومة، بطاقاتٌ غير مكتوبة، أهدافٌ فارغة) — نبّه المستخدم صراحةً بدل بناء أداةٍ لمشكلةٍ غير موجودة.
